Capítulo 1 — Introducción y alcance

1.1 Objetivo del manual

Este manual describe, paso a paso y con el detalle necesario para operar en producción, el Sistema de Gestión de Ensayos del CTM (Centro Tecnológico del Mueble). Cubre desde el ingreso al sistema hasta la emisión de informes y la gestión de documentos PDF asociados a cada ensayo.

1.2 Perfiles de usuario

PerfilCódigoOperaciones principales
ClienteCLIENTAlta de clientes, solicitud de ensayos, consulta y descarga de documentos
LaboratorioLABORATORYAprobación, contratos, recepción, resultados, informes, configuración

1.3 Flujo general del ensayo

Solicitud (REQUESTED) → Aprobación (ACCEPTED) o Rechazo (REJECTED) → Contrato (SERVICE_AGREEMENT_MADED) → Recepción de muestras → Orden de trabajo (IN_WORK) → Carga de resultados → Emisión de informe (COMPLETED) Estados terminales: REJECTED · CANCELLED

1.4 Documentos generados

CódigoNombreMomento
F-PC13-01Solicitud de ensayoAl crear solicitud
F-PC13-02Contrato de servicioAl generar contrato
F-PC16-01Registro recepción muestrasAl aceptar muestras
F-PC16-02Orden de trabajoFlujo laboratorio
F-PC15-01Informe de ensayoAl emitir informe

Capítulo 2 — Inicio de sesión

2.1 Requisitos previos

  • Usuario y contraseña activos.
  • Navegador actualizado (Chrome, Firefox o Edge).
  • URL: oficina.ctmueble.com.ar.

2.2 Acceder al sistema

  1. Abrir la pantalla de Inicio de sesión.
  2. Ingresar correo electrónico y contraseña.
  3. Presionar Ingresar.
Resultado esperado: acceso al panel principal con módulos según perfil.

2.3 Selección de laboratorio y perfil

  1. Ir a configuración de usuario o selector de laboratorio.
  2. Elegir el laboratorio activo.
  3. Si corresponde, cambiar perfil (CLIENT / LABORATORY).

2.4 Cierre de sesión y renovación de token

Use Salir para cerrar sesión. Si la sesión expira, ingrese nuevamente. El sistema puede renovar el token con refresh token si la sesión sigue vigente.

2.5 Problemas frecuentes de acceso

SituaciónCausaAcción
Credenciales incorrectasDatos erróneosVerificar o solicitar restablecimiento
Demasiados intentosRate limitEsperar e intentar de nuevo
Acceso denegadoPerfil incorrectoCambiar a LABORATORY
Token inválidoSesión vencidaCerrar sesión e ingresar

Capítulo 3 — Configuración del sistema (variables de entorno)

3.1 Qué son las variables de entorno

Parámetros de negocio almacenados en la base de datos (environment_variables) que alimentan las plantillas PDF. Definen datos institucionales: razón social, CUIT, domicilio, director, datos bancarios, incertidumbre.

Solo usuarios con perfil LABORATORY pueden consultar y modificar estas variables.

3.2 Acceder al módulo

  1. Iniciar sesión con perfil LABORATORY.
  2. Ir a Configuración → Variables de entorno (API: GET /env/fetch).

3.3 Consultar variables existentes

Revisar identificador, etiqueta, tipo y valor. Para una variable puntual: GET /env/get?id=...

3.4 Modificar una variable

  1. Seleccionar la variable.
  2. Ingresar nuevo valor según tipo: TEXT, NUMBER, DECIMAL o TIMESTAMP.
  3. Guardar (PUT /env/update?id=...).
Los documentos generados a partir de ese momento incluirán el valor actualizado.

3.5 Agregar variable personalizada

Completar ID, etiqueta, tipo y valor (POST /env/add).

3.6 Eliminar una variable

Solo variables no hardcoded (DELETE /env/delete?id=...).

3.8 Impacto en documentos PDF

Al generar formularios, el sistema obtiene variables en modo DATA, las fusiona con datos del ensayo y renderiza PDF con Handlebars + Puppeteer.

Capítulo 4 — Sistema de clientes y empresas

Referencia cruzada: consultar este capítulo durante la carga de solicitud de ensayo (Cap. 5, pasos 3 y 4).

4.1 Conceptos

ConceptoDescripción
EmpresaEntidad fiscal por CUIT y razón social
DirecciónDomicilio operativo; varias por CUIT
PersonaRepresentante, contacto o tercero
ClienteVínculo: empresa + dirección + personas + facturación
SnapshotCopia del cliente al crear el ensayo (essays_client)

4.2 Buscar empresa por CUIT

  1. Ir a Empresas / Clientes.
  2. Ingresar CUIT y buscar.

4.3 Sincronizar desde ARCA/AFIP

  1. Buscar CUIT inexistente.
  2. Seleccionar Sincronizar desde padrón (POST /bussiness/sync/).
Solo personas jurídicas. Si falla, crear manualmente (4.4).

4.4 Crear empresa manualmente

CUIT + razón social → POST /bussiness/manual/

4.5 Gestionar direcciones

Agregar, editar o eliminar direcciones: calle, localidad, provincia, distrito opcional.

4.6 Representantes y contactos

Representante: opcional. Contacto del ensayo: obligatorio. Crear o seleccionar persona; vincular contactos adicionales.

4.7 Alta de cliente completo

  1. CUIT de empresa.
  2. Dirección.
  3. Representante (opcional).
  4. Contacto principal.
  5. Facturación alternativa.
  6. Guardar → POST /clients/create.

Atajo: GET /bussiness/for-essay/?cuit=... y POST /clients/get-or-create-for-essay.

4.8 Facturación alternativa

CUIT, dirección, localidad, provincia y tributa IVA — opcionales en el cliente.

4.9 Buscar, editar y eliminar

/clients/fetch · /clients/search · /clients/update · /clients/delete

4.10 Clientes agendados

Laboratorio puede agendar clientes frecuentes: POST /clients/scheduled.

Capítulo 5 — Solicitud de ensayo

5.1 Cuándo y quién puede crear

Perfiles CLIENT y LABORATORY. Cliente debe existir (Cap. 4). Estado inicial: REQUESTED. Se genera F-PC13-01.

5.2 Paso 1: Módulo de ensayos

Panel → Ensayos. Filtrar por código, estado o fechas.

5.3 Paso 2: Nueva solicitud

Nueva solicitud / Crear ensayo.

5.4 Paso 3: Cliente

Opción A — Cliente existente

Buscar por CUIT o nombre → seleccionar.

Opción B — Cliente nuevo

Ingresar CUIT → sincronizar/crear empresa → completar datos → Capítulo 4.

El sistema crea snapshot en essays_client al confirmar.

5.5 Paso 4: Contacto del ensayo

Seleccionar persona de contacto. Verificar mail y teléfono.

5.6 Paso 5: Tipo de ensayo

Selector de tipo (GET /essays/get-types).

5.7 Paso 6: Datos del producto/material

CampoReq.Descripción
PlantillaSíelements.template — precarga producto, fabricante, país
FechaSíyyyy-MM-dd
Nº de loteNoOpcional

5.8 Paso 7: Observaciones

Texto libre: condiciones especiales, referencias, instrucciones de recepción.

5.9 Paso 8: Facturación

CampoReq.Notas
CUIT a facturarSíDebe existir en empresas
DirecciónNoPuede heredarse del cliente
MontoNoCLIENT no puede fijar monto
Tributa IVASíDefault: no

5.10 Paso 9: Confirmar

  1. Revisar resumen.
  2. Confirmar → POST /essays/create.

Sistema genera código (yyyymmdd+letra), registros en BD, auditoría y F-PC13-01.

5.11 Resultado esperado

Estado REQUESTED · código de seguimiento · F-PC13-01 descargable

Capítulo 6 — Evaluación de la solicitud

6.1 Estados iniciales

Solo desde REQUESTED se aprueba o rechaza.

6.2 Aprobar (ACCEPT)

Abrir ensayo → Aprobar → estado ACCEPTED.

6.3 Rechazar (REJECT)

Observaciones opcionales → Rechazar → REJECTED.

6.4 Cancelar (CANCEL)

Motivo en observaciones → CANCELLED.

Capítulo 7 — Generación de contrato

7.1 Requisitos

Estado ACCEPTED · perfil LABORATORY.

7.2 Paso 1: Abrir ensayo aprobado

Filtrar ACCEPTED → abrir detalle.

7.3 Paso 2: Términos

CampoDescripción
days_to_doPlazo en días
pricePrecio acordado
samples_conservation_daysDías conservación muestras

7.4 Paso 3: Generar F-PC13-02

Generar contrato → POST /essays/generate-contract

7.5 Paso 4: Verificar

Estado SERVICE_AGREEMENT_MADED · F-PC13-02 disponible

Capítulo 8 — Recepción de muestras

8.1 Requisitos

SERVICE_AGREEMENT_MADED · LABORATORY · muestras físicas recibidas.

8.2 Paso 1: Localizar ensayo

Buscar por código o CUIT.

8.3 Paso 2: Recepción

Recepción de muestras → POST /samples/receive-samples

8.4 Paso 3: Aceptación o rechazo

accepted: true/false

8.5 Paso 4a: Rechazo

Observaciones → ensayo CANCELLED. Sin OT ni muestras.

8.6 Paso 4b: Aceptación — cantidades

samples_count y countersamples_count (al menos uno > 0).

8.7 Paso 5: Dimensiones

height, width, thickness (cm) · internal_conditioning · observations.

8.8 Paso 6: Confirmar

Revisar y confirmar.

8.9 Resultados automáticos

  • Orden de trabajo con código y plazo de informe
  • Muestras con correlativos
  • Estado IN_WORK
  • F-PC16-01 generado
  • Auditoría SAMPLES_RECEIVED

Capítulo 9 — Carga de resultados

9.1 Requisitos

OT con muestras · LABORATORY · IN_WORK.

9.2 Paso 1: Abrir OT

Órdenes de trabajo → buscar → abrir.

9.3 Paso 2: Visualizar muestras

Código, correlativo, contramuestra, dimensiones, estado.

9.4 Paso 3: Resultado por muestra

{
  "workOrderId": "uuid-orden",
  "samples": [
    { "id": "uuid-1", "result": 12.5 },
    { "id": "uuid-2", "result": 12.3 }
  ]

9.5 Paso 4: Guardar

Promedio recalculado · auditoría RESULTS_LOADED

9.6 Validaciones

  • Muestras deben pertenecer a la OT
  • Resultado numérico válido
  • Solo LABORATORY
